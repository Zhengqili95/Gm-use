# vibe-learn 規格書

> 狀態：**已定案**（2026-10-18，見 `team/DECISIONS.md` 的 D-008）。要修改任何一項，都要先在討論區提出，經使用者同意。
> 每一輪的問答紀錄在最後的「附錄：訪談紀錄」。

## 1. 一句話說明

免費的 AI 時代學習平台：教不太懂程式、但想用 AI 做出作品的人「AI 時代的軟體基礎」，另外附一個只有使用者自己能用的「問 AI」功能。

## 2. 目標與學習者

- **第一階段**：給使用者自己和身邊的人（同學、朋友）用，邊做邊學；做穩了再考慮公開。
- **學習者**：想用 AI 做作品、但不太懂程式的人，例如大學生、非資訊科系的人。使用者本人是第一個學生。
- **參考對象**：哈利的「氛圍學院」（互動式、個人化的學習平台）。只參考形式，課程內容、名稱和品牌全部自己做。

## 3. 限制

- **費用**：營運成本 0 元。學習者免費，使用者也不付任何月費。
- **時程**：1 個月內做出第一版，目標在 2026-11-18 前完成。
- **語言**：繁體中文為主；開發用語保留英文，第一次出現時附中文說明，例如「API（應用程式介面）」。
- **名稱**：暫定 vibe-learn，第一版做完再取正式名稱。

## 4. 課程

- **每一課的組成**：短文說明（有圖解和例子）、互動練習、小測驗。第一版不做影片。
- **長度**：每課 15～20 分鐘，一課只學一件事，學完有一個看得到的成果。
- **第一版的課數和主題**：3 課（D-012），順序依 D-011，課名依 D-013：
  1. **畫面是怎麼拼出來的**：HTML、CSS、JavaScript（練習：即時預覽）。只教三件事：看懂標籤結構、用 CSS 改顏色和間距、用 JavaScript 讓按鈕改變文字。開頭用一小段帶過「網頁是怎麼來的」的大觀念。
  2. **網頁怎麼跟外界拿資料**：瀏覽器、伺服器、request／response（練習：模擬 API）。
  3. **資料怎麼存下來不消失**：資料庫入門（練習：瀏覽器裡的 SQLite）。只教欄位與資料表、`SELECT`、`INSERT`、`UPDATE`，不教 `JOIN`。
- **還沒做好的課**（D-013）：設成草稿（`draft: true`），正式網站上不顯示；首頁標成「即將推出」、不放連結；進度的分母只算已經上線的課。
- **共用範例**（D-012）：三課都圍繞同一張「AI 提示詞收藏卡」：第 1 課做出卡片，第 2 課改成向伺服器要資料，第 3 課看資料存在資料庫的哪裡。
- **製作順序**（D-011）：全隊先集中做完第 1 課、跑通整條流程，再做第 2、3 課；「問 AI」由一位成員同時進行。
- **互動練習**：全部在瀏覽器裡執行，不用安裝任何東西。三種練習元件：前端即時預覽、模擬 API、瀏覽器內的 SQLite。練習一律是「改一小段」（填空、改一個值、補一行），不從零開始寫（D-012）。
- **批改**（D-012）：自動檢查，而且看的是執行結果（畫面的狀態、送出的請求和收到的回應、查詢出來的資料），不比對程式碼字串。答錯時提示分三層：觀念提醒 → 該檢查哪裡 → 語法範例，最後再讓學習者選要不要看答案。
- **圖解**（D-012）：用內嵌 SVG，會跟著深色模式變色；第一版不做封面圖和情境圖。
- **可選加項**（D-012）：「和 AI 一起用」（3 句範例提示＋怎麼檢查 AI 給的結果）和「本課英文用語」小表，先在第 1 課試做，試讀時再決定要不要留。
- **內容把關**：三道關卡都過才上線：
  1. 每一課都附可信的參考來源（例如 MDN 這類官方文件）。
  2. 另一個 AI 交叉審查內容正不正確。
  3. 使用者試讀，看得懂才上線。
- **朋友的回饋**：每一課最下面放「回報問題／給建議」連結，連到使用者建立的 Google 表單。

## 5. 平台

- **形式**：網站，電腦和手機的瀏覽器都能用。
- **技術**：Astro + Starlight（現成的課程／文件版面），再改顏色和字型，加上練習和測驗元件。
- **感覺**：清爽好讀為主，加上輕量的進度感：每課完成打勾、測驗分數、整體進度條。
- **帳號與進度**：不做登入。學習進度存在瀏覽器裡，換電腦或清除瀏覽器資料就會不見。
- **發布**：GitHub Pages。免費方案的 repo 要公開；`team/` 不會上傳。GitHub 只用來發布網站，協作方式不變（D-003）。

## 6. 「問 AI」功能（只在使用者的電腦上）

- **用途**：學習時卡住，直接在課程頁面上提問。
- **範圍**：只有在使用者的電腦上執行平台時才會出現；GitHub Pages 上給朋友用的版本沒有這個功能。訂閱帳號是個人使用的，不能開放給朋友用。
- **運作方式**：本機的小伺服器（只接受這台電腦的連線）在背景呼叫 Claude Code（`claude -p`），用主帳號的訂閱額度，不需要 API key。
- **AI 看得到的內容**：只有這一課的內容、學習者的練習程式碼和問題。AI 不能讀其他檔案、不能改檔案、不能執行指令。
- **回答方式**：先給提示，一鍵就能看完整答案。用繁體中文、保留英文術語，最後附「本次英文用語」小表。
- **問答紀錄**：預設不存；每次回答後由使用者選要不要存，存的話只存在使用者的電腦上。
- **Codex**：第二步再加（等 Codex 回覆 M-005、M-006，而且 Claude 版跑穩之後），屆時可以切換回答的 AI。
- **優先順序**：第一版一定要有，分工時讓一位成員專門負責，和課程同時進行。

## 7. 第一版的完成標準

下面四項都做到，才算第一版完成：

1. T-002 決定的每一課，都通過三道品質關卡。
2. 網站已經上線到 GitHub Pages，手機和電腦都能正常使用。
3. 在使用者的電腦上，可以用「問 AI」向 Claude 提問，先給提示、可以一鍵看答案。
4. 至少 2 位朋友實際試用過，並且填過回饋表單。

## 8. 已知風險與待確認事項

- `claude -p` 的參數組合（例如 `--tools ""`）還沒有實際呼叫模型測試過，做「問 AI」時要先測。
- `claude -p` 預設會載入使用者的全域設定（`~/.claude/CLAUDE.md`），可能影響回答格式，實作時要處理。
- 主帳號屬於學校的組織（Team 方案）；如果組織另有使用規範，以組織規範為準。
- 「問 AI」會用到主帳號的 5 小時與每週額度，和平常使用 Claude 共用。
- 發布前要確認：使用哪個 GitHub 帳號、repo 名稱。
- 使用者要自己建立 Google 表單，拿到連結後交給 AI 團隊。

### 「問 AI」技術調查（2026-10-18，背景研究加上本機檢查，還沒實際呼叫模型測試）

- **Claude Code**：可以用 `claude -p` 在背景回答。加上 `--tools ""` 會拿掉所有內建工具，就不能讀寫檔案或執行指令；另外要加 `--strict-mcp-config` 和 `--permission-mode dontAsk`。指令版目前登入的是主帳號（Team 方案），用量算在這個帳號的 5 小時與每週額度裡。這台電腦沒有設定 `ANTHROPIC_API_KEY`，所以不會改走付費 API。
- **規則**：使用者自己用可以；讓朋友透過平台使用不行（等於共用帳號）。這和第二輪「只在使用者電腦上能用」的決定一致。主帳號屬於組織，如果組織另有使用規範，以組織規範為準。
- **Codex**：Codex App 內附 `codex.exe`，路徑會隨 App 更新改變，所以程式要自動尋找。指令版和 App 共用 ChatGPT 登入（`codex login status` 顯示已登入）。`codex exec` 預設在唯讀沙箱裡執行。官方把「用 ChatGPT 登入做自動化」列為進階用法；`codex mcp-server` 已經被移除。細節等 Codex 回覆 M-005、M-006。
- **Gemini**：沒有辦法從程式呼叫 Gemini App；Gemini CLI 的個人免費方案已在 2026-06-18 停止。Gemini 維持由使用者轉貼的角色，不參與「問 AI」。
- **注意**：`claude -p` 預設會載入使用者的全域設定（`~/.claude/CLAUDE.md`），回答的格式可能受影響，實作時要處理。
